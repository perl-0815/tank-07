# 『水槽07』
UI / Visual Requirement Specification

## 1. UIコンセプト

ゲーム全体は、

「海底研究施設との旧式非常通信端末」

を操作しているように見せる。

現代的なメッセンジャーUIではなく、

- 古い研究施設
- 軍用・産業用端末
- CRTモニター
- 海底通信
- 不安定な非常回線

を感じるデザインにする。

ただし、完全なレトロPC風にはしない。

操作性は現代的で分かりやすく、
見た目だけにレトロ感を持たせる。

---

# 3. 画面構成

## 3-1. ヘッダー

表示項目：

左側：

ABYSSAL-7

EMERGENCY COMMUNICATION TERMINAL

または、

ABYSSAL-7 // EMERGENCY LINK

中央または左下に小さく：

DEPTH : 3200m

CHANNEL : AUX-07

SIGNAL : 63%

右側：

残り時間

例：

02:47

---

## 3-2. タイマー

タイマーは常に表示。

通常時：

02:47

残り60秒：

01:00以下で軽く警告表示。

残り30秒：

文字の揺れやノイズを増やす。

残り10秒：

SYSTEM ALERT表示。

例：

```text
00:10

SIGNAL INSTABILITY DETECTED
```

タイマーが0になると通信切断。

---

# 4. チャットログ

画面中央の大部分を使用。

縦スクロール形式。

会話は以下3種類。

## YUNA

```text
YUNA
聞こえる？
```

## PLAYER

```text
> 今どこにいる？
```

## SYSTEM

```text
[SYSTEM]
CONNECTION ESTABLISHED
```

---

# 5. 発言デザイン

吹き出し型にはしない。

端末ログのような表示。

例：

```text
YUNA // 02:43

聞こえる？
```

PLAYER：

```text
YOU // 02:39

> 聞こえる
```

SYSTEM：

```text
[ SYSTEM ]

AUXILIARY LINK ESTABLISHED
```

チャットアプリではなく
「通信記録」に見えることを優先。

---

# 6. テキスト表示アニメーション

YUNAの発言は、

瞬間表示ではなく少しずつ表示。

1文字ずつではなく、

数文字単位の高速タイプ表示。

例：

```text
聞こ
聞こえる
聞こえる？
```

速度：

20〜40ms程度。

重要なセリフでは少し遅くしてよい。

---

# 7. 入力中演出

YUNAが返信する前に、

```text
YUNA IS TRANSMITTING...
```

を表示。

ただし毎回長時間待たせない。

0.3〜1秒程度。

重要シーンのみ、

```text
YUNA IS TRANSMITTING...

...

CONNECTION DELAY
```

などを使う。

---

# 8. 選択肢UI

画面下部。

最大3〜4択程度。

例：

```text
[ 何が起きた？ ]

[ 今どこにいる？ ]

[ 名前は？ ]
```

ボタンというより、

ターミナルのコマンド候補に見えるデザイン。

例：

```text
> 01 WHAT HAPPENED
> 02 LOCATION
> 03 IDENTIFY
```

日本語表示でもよい。

---

# 9. 選択肢のホバー / 選択演出

ホバー：

軽く発光。

左側にカーソル。

```text
> 今どこにいる？
```

クリック：

一瞬ノイズ。

その後PLAYERログに追加。

---

# 10. キーワード入力

画面最下部。

```text
KEYWORD >
```

入力例：

```text
KEYWORD > 7319
```

送信すると、

```text
YOU

> 7319
```

としてチャットログに表示。

---

# 11. キーワード候補

過去に取得した情報については、
補完候補を表示してもよい。

例：

```text
KEYWORD >

7319
TANK-07
ISOLATION
YUNA
```

ただし、
未知のキーワードも入力可能。

---

# 12. 通信ノイズ

常時ごく薄くノイズを入れる。

強すぎないこと。

種類：

- CRT走査線
- 微細な粒子ノイズ
- 水平方向の画面ズレ
- 文字の一瞬の欠け
- 信号乱れ

---

# 13. 通常時ノイズ

非常に弱い。

5〜15秒に一度程度、

画面が1〜3px水平にズレる。

テキストの一部が一瞬だけ乱れる。

例：

```text
CONNECTION
CONNEC█ION
CONNECTION
```

---

# 14. 強ノイズイベント

事故イベント時。

0.2〜0.5秒程度。

例：

- 画面全体が横方向にずれる
- RGB分離
- SYSTEMログの文字化け
- 画像にブロックノイズ

---

# 15. 通信切断演出

タイマー0。

まず：

```text
SIGNAL LOST
```

画面ノイズ増加。

YUNA：

```text
待っ――
```

途中で途切れる。

その後：

```text
CONNECTION TERMINATED
```

暗転。

0.5〜1秒。

再接続。

---

# 16. 周回開始演出

黒画面。

```text
RECONNECTING...

AUX CHANNEL 07

SEARCHING...

SIGNAL FOUND
```

そして、

```text
YUNA

聞こえる？
```

同じ開始メッセージ。

周回回数は明示しなくてもよい。

---

# 17. SYSTEMログ

世界観表現に積極的に使う。

例：

```text
[SYSTEM]
PRESSURE DROP DETECTED
```

```text
[SYSTEM]
SECTION-04 LOCKDOWN
```

```text
[SYSTEM]
UNKNOWN SIGNAL DETECTED
```

これにより、
チャットだけで施設全体の状況を表現する。

---

# 18. 画像添付機能

YUNAから画像が送られる。

画像はチャットログ内に表示。

例：

```text
YUNA

これ見える？

[ IMAGE_004 ]
```

画像カードをクリックすると拡大。

---

# 19. 画像カードUI

表示例：

```text
┌──────────────────┐
│ IMAGE ATTACHMENT    │
│                    │
│      preview       │
│                    │
│ SIGNAL QUALITY 71%  │
└──────────────────┘
```

画像下部：

```text
IMG_004
CAMERA-07
```

---

# 20. 画像表示エフェクト

画像は最初から鮮明ではない。

受信時：

1.
黒いカード表示

2.
走査線

3.
画像が上から少しずつ表示

4.
ノイズが消える

表示時間：

0.5〜1秒程度。

---

# 21. 画像ノイズ

画像によって状態を変える。

通常：

軽いJPEGノイズ風。

通信障害時：

- ブロックノイズ
- 横線
- 一部欠損
- 色ずれ
- 暗部潰れ

# 23. 画像演出ルール

画像は、

「状況説明」

よりも、

「プレイヤーが疑問を持つための材料」

として使用する。

説明しすぎない。

特に、

IMG_05

IMG_06

IMG_08

IMG_10

は、

見れば答えが分かる画像

ではなく、

「何かおかしい」

と感じる画像にする。

---

# 24. YUNAの姿

YUNAの顔は基本的に見せない。

理由：

チャット相手が本当にYUNAなのか

という疑問を維持するため。

画像に人物が写る場合も、

- 後ろ姿
- 遠距離
- 監視カメラ
- 暗い
- 顔がノイズで潰れている

などを使う。

---

# 25. 色設計

基本：

黒〜暗い青灰色。

アクセント：

青緑。

警告：

赤。

SYSTEM：

グレー〜白。

YUNA：

淡い青。

PLAYER：

白。

UNKNOWN：

通常色から微妙に外す。

例えば薄い灰白色。

---

# 26. フォント

英数字：

等幅フォント。

例：

JetBrains Mono
IBM Plex Mono
Space Mono

日本語：

読みやすいゴシック。

例：

Noto Sans JP

英数字のみ少しレトロな等幅にする。

---

# 27. CRT表現

画面全体に以下を薄く適用。

- scanline
- vignette
- noise
- bloom

ただし、

文字が読みにくくなるほど強くしない。

---

# 28. 背景

基本背景は暗色。

完全な黒ではなく、

非常に暗い青。

画面端に、

微かな水中粒子のようなノイズを表示してもよい。

---

# 29. 水中感

海中そのものを背景に表示しない。

端末を操作している感覚を維持する。

代わりに、

低い環境音

通信ノイズ

遠くの金属音

などで深海を表現する。

---

# 30. アニメーション

基本：

短く、控えめ。

使用するもの：

- タイプ表示
- フェード
- 軽いグリッチ
- 画面揺れ
- 信号ノイズ
- 画像ロード

避けるもの：

- 大きな派手なトランジション
- ゲームUIらしいポップアニメーション
- 過剰なネオン演出

---

# 31. 重要シーン演出

## 初接続

静か。

SYSTEMログ中心。

---

## 最初の浸水

軽い画面揺れ。

ノイズ増加。

SYSTEM警告。

---

## YUNA正体疑惑

ノイズを減らす。

むしろ静かにする。

返信時間を長くする。

---

## 水槽07映像

画面全体を暗く。

画像だけ視線を集める。

---

## UNKNOWN初登場

通常のYUNAメッセージと同じ場所から表示。

ただし送信者名：

UNKNOWN

一瞬だけ表示崩れ。

---

# 32. UNKNOWN演出

最初は派手にしない。

例：

```text
UNKNOWN

こんにちは
```

だけ。

その後に、

UIの一部だけが微妙に変化。

例：

```text
CHANNEL : AUX-07
```

が、

```text
CHANNEL : 07
```

になる。

---

# 33. 音

必須ではないが推奨。

環境：

- 低い機械音
- 遠い金属音
- 通信ノイズ

UI：

- メッセージ受信音
- 選択音
- SYSTEM警告音

重要：

音量は控えめ。

突然の大音量は使わない。

---

# 34. レスポンシブ

PC優先。

スマートフォンでもプレイ可能。

PC：

中央に端末画面。

最大幅：

800〜1000px程度。

モバイル：

ほぼフルスクリーン。

選択肢を下部固定。

---

# 35. UIの優先順位

最優先：

1.
文章の読みやすさ

2.
選択肢の押しやすさ

3.
タイマーの視認性

4.
世界観

5.
演出

レトロ演出によって操作性を悪化させない。

---

# 36. 目指す印象

プレイヤーが画面を見た瞬間、

「ゲームのチャット画面」

ではなく、

「本当にどこかの海底施設につながってしまった端末」

と感じるUIにする。

ただし操作は、

チャットアプリのように直感的。

この二つを両立させる。
